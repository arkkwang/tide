# 待验证问题

## 快照 token 消耗与工具调用轮次

用户反馈：工具可用，但多次读取完整屏幕可能导致 token 消耗快速增长；发送、等待、抓屏分开调用也增加 Agent 的工具调用轮次。

当前改进：`send` 的文本 / `--key` 模式可组合 `--wait-idle`、`--with-capture`，减少调用方往返。仍返回完整快照，尚未解决重复屏幕内容的 token 消耗。

后续验证：选取典型交互任务，统计完成任务的工具调用次数、返回文本量和实际 token 用量，识别重复或无关内容占比；再比较按需抓屏、输出裁剪或增量返回等方案。不能为了缩短输出而丢失权限提示、错误或 TUI 重绘后的有效信息。目前未选定方案。

## 多个 capture 是否互相影响

用户提出：多个工具调用中出现不同 capture 时，是否会相互影响，需要专门验证。

待区分和验证的情况：

- 不同 Session 并发抓屏，是否存在画面串线或归属混淆。
- 同一 Session 并发或交错抓屏，尤其参数不同、期间有输入/输出/resize/切换缓冲区时，是否会改变彼此结果。
- 多个 Agent 共享同一 Session 时，较旧的快照是否会被当作最新状态用于决策；组合发送、等待、抓屏期间也可能有人继续输入。

验证应同时检查实现中的状态隔离、返回结果的一致性，以及调用方能否正确理解快照的归属和时序。在证据明确前，不承诺这些调用构成原子操作，也不预先引入锁或缓存方案。
