# 终端读取的当前边界与待验证问题

## 已落地：按命令区域省略已读历史

公开入口统一为 `read` / `--with-read`，不保留 `capture` CLI 别名。Bash 4.4+ 通过 PS1 / PS0 发出 OSC 133 提示符与执行标记；xterm 行标记随滚动定位命令区域。默认保留整个当前/最近命令区域，以及前面尚未读取的结果；只省略连续的已读历史前缀，不逐行压缩进度画面。

`--lines N` 是所选范围的末尾行数上限，不补足历史；`--full` 关闭历史省略，也可以与 `--lines` 组合。默认命令区域不受窗口高度限制，仍受现有缓冲区及最多 2000 个显示行约束。超长单行/整体字符限制本轮不做。

读取记录只存在于 Session 内存，一个 Session 对应一个 Agent；独立与组合读取共用记录，不引入读取者 ID。插件的内部 `capture()` 和 idle 检测保持原来的无状态完整画面，不消耗读取记录。丢失 RPC 响应可能已更新记录，调用方可以 `--full` 补读。

## 验证范围

单元测试覆盖多行进度原地更新、中间未变化行、滚屏、相同命令与输出再次出现、命令完成后继续读取、读后新增输出、未读的多个命令、行数上限、不足行数不补历史、完整历史读取、会话隔离、alternate screen、清屏/resize、超过窗口高度和历史缓冲容量。

真实 PTY 集成测试覆盖 Bash 标记传输、默认省略前一条结果、`--full` 补读、独立与组合读取、插件隔离、公开参数及启动命令流程。Windows 本机验证；macOS 与其他 shell 启动配置仍需实机验证。

## 当前限制

- 无标记的 shell、旧 Bash 和全屏 alternate-screen TUI 默认返回当前画面，不猜测任务边界。
- 清屏或尺寸变化重置区域记录；后续新标记恢复追踪。历史已被缓冲区淘汰时无法恢复。
- 启动文件覆盖 PROMPT_COMMAND、其他 shell 集成或嵌套交互 shell 可能影响标记，需要按真实配置验证。OSC 标记是显示层线索，不是可信执行审计或退出状态。
- 读取、发送和等待不构成原子事务；用户仍可手动输入。多 Agent 独立已读状态明确不在当前范围内。
- 尚未测量真实任务的 token 节省比例，不以测试通过代替使用收益数据。
